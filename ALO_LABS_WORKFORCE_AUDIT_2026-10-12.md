### 1.1 Architecture map (workforce layer)

```
department-registry (100 depts, agentCount 20)
        │
        ▼
workforce/plan.ts ── deterministic: dept N owns AGENT-(N-1)*20+1 .. N*20
        │             first role = department orchestrator
        │             approved tools = dept tools ∩ role category (fallback: first dept tool)
        │             forbidden tools = global list ∪ dept tools not approved
        │             modelConfig.pinnedModel = null (router resolves at runtime)
        │             queue = agentos, partition agent:<id>
        ▼
workforce/provision.ts ── WorkforceStore port (loadAll / create / update / dryRun)
        │   creates missing rows; updates only rows it manages (runtimeProfile.provisioning.managedBy)
        │   refuses unowned or cross-tenant rows (conflict, no write); never writes status on update
        ▼
workforce/prisma-store.ts ── Prisma adapter (SQLite via driver adapter; MySQL schema mirrors it)
        │
        ▼
workforce/verify.ts ── 13 configuration checks + drift + lifecycle counts (no operational claim)
```

Sensitive actions (`external_send`, `payment`, `delete_record`, `publish_content`, `grant_access`, `change_permissions`) always require human approval (`roles.ts: SENSITIVE_ACTIONS`). Globally forbidden tools are listed in `roles.ts: GLOBALLY_FORBIDDEN_TOOLS`.

## 6. Deployment plan (proposed — NOT executed)

1. **Review:** this PR, the audit, and the inventories in `docs/workforce/`.
2. **Staging:** restore a staging snapshot. Apply `20261012_workforce_provisioning.sql` to a MySQL 8 copy (B4). Note: `sqlite-push` only creates missing tables and refuses existing databases with undeclared foreign keys, so it cannot migrate an existing SQLite database. Existing SQLite data needs a reviewed table-rebuild migration first.
3. **Dry-run:** `npm run provision:workforce:dry-run`. Expected: 100 / 2,000, 0 conflicts. Any conflict → resolve per B2 before continuing.
4. **Apply:** `npm run provision:workforce`. Then `npm run verify:workforce`. Expected: `ok: true`, `agentsOwned: 2000`, `agentsOperational: 0`.
5. **Runtime verification (not yet built):** execute a representative task per department; verify tool calls, persistence and completion. Only then promote agents from `provisioned` to `active`.
6. **Rollback:** `20261012_workforce_provisioning_rollback.sql` (drops tenant columns and profile data; take a backup first). Roll back the application release before the schema.
7. **Production:** only after explicit authorization (B7).
